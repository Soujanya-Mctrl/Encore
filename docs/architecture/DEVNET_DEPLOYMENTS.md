Each entry in [DEVNET_DEPLOYMENTS.json](DEVNET_DEPLOYMENTS.json) preserves the network, program address, ProgramData address, finalized slot and transaction, UTC block time, public upgrade authority and binary SHA-256. The generated IDL pins the program address in the web client.

For an authorized upgrade, run `pnpm chain:build`, `pnpm chain:generate`, and `pnpm chain:deploy:devnet`. The deploy command checks the keypair against the pinned address and saves a new history entry after finalization. If RPC finality is delayed, run `pnpm chain:record:devnet` to verify and record the result without submitting another deployment. Keep the JSON history with the code change. An upgrade normally keeps the same program address. A deliberate move to a new address requires updating `declare_id!`, `Anchor.toml`, and the public environment value, then regenerating the IDL before deployment. Preserve previous entries because their Passports still reference the older program.

The build uses [Anza platform-tools v1.54](https://github.com/anza-xyz/platform-tools/releases/tag/v1.54) and the `sbpf-solana-solana` target. Set `ENCORE_PLATFORM_TOOLS` if the toolchain is outside `.local/toolchain/platform-tools-v1.54`. The default deployer, program keypair and binary paths are under ignored `.local/`. `ENCORE_REGISTRY_DEPLOYER`, `ENCORE_REGISTRY_KEYPAIR` and `ENCORE_REGISTRY_BINARY` override their respective paths. Store signing keys separately from this deployment history.
